# 실운영 트래픽 기반 예산 분석 — Vercel Pro + R2 + Supabase (2026-07)

## 0. 실측이 바꾼 전제 (중요)

`serverless_vs_selfhosted.md`는 *"회원 300명, 트래픽은 한도의 10% 미만"*을 가정했으나, 실측은 **실운영 트래픽**을 보여준다:

| 지표 | 옛 가정 | **실측 (2026-06-25)** |
|---|---|---|
| 일 조회수(Hits) | 저트래픽 | **62,714** (≈ 1.9M/월) |
| 일 방문자 | ~수십 | **7,221** / 접속 IP 1,354 |
| 월 egress | "5GB 근처도 안 감" | **~90GB/월** (일 3.1GB) |
| 회원 | ~300 | **3,025 등록** (실활성 ~250–300) |
| 콘텐츠 | — | 글 41,727 · 댓글 61,981 · 9종 권한 |
| 미디어 | "~38GB(추정)" | 첨부 실측 **19.66GB** (이관 페이로드 8–12GB) |

→ **트래픽은 사소하지 않다.** 다만 90GB의 대역폭 집중원은 **미최적화 대용량 사진**(메인 ~5MB JPG 반복 전송)이며, 이는 **미디어를 R2로 오프로딩**하면 대부분 무료 egress로 흡수된다. 즉 아키텍처(정적 셸 + R2 미디어 + 클라 개인화)는 유효하되, **"월 0원" 전제 중 Vercel Hobby 부분은 Pro로 현실화**해야 한다(62K hits/day는 Hobby 비상업 약관·하드캡에 저촉).

## 1. 핵심 설계: 미디어는 Vercel을 거치지 않는다

공개 이미지는 **R2 커스텀 도메인 직링크(CDN 캐시)**로 서빙된다(media_storage_strategy §5.2). 따라서 90GB의 대부분이 **R2 egress(무료)**로 빠지고, **Vercel에는 HTML/RSC/JS/JSON만 남는다(추정 15–30GB/월).** 회원 콘텐츠도 클라이언트가 Supabase를 **직접** 호출하므로(정적 셸 + 클라 아일랜드) Vercel 함수 호출은 서버액션·`/dl` 프록시·auth 콜백 정도로 최소화된다.

## 3. 자동 스케일아웃 / 초과 대응

| 플랫폼 | 스파이크·초과 시 동작 |
|---|---|
| **Vercel Pro** | **자동 스케일(종량 과금).** 초과분은 **Spend Management 예산**(기본 $200, 조정 가능)까지 자동 청구되며 **서비스가 끊기지 않음**. 100% 도달 시 *선택적으로* 전 프로젝트 하드 정지 설정 가능. → **Hobby(하드 캡=사이트 중단/스로틀)와 정반대. Pro는 스파이크를 흡수하고 과금**, 상한은 우리가 설정. |
| **Cloudflare R2** | 종량제, 기본 하드캡 없음. **egress 무료라 트래픽 폭증에도 egress 청구 0** → 가장 스파이크 내성 큼. 저장·연산만 종량. |
| **Supabase Pro** | 250GB egress 포함, 초과 시 $0.09/GB 자동 과금. **Spend Cap ON**이면 한도에서 제한(다음 청구주기·업그레이드까지 해제), OFF면 종량 과금. |

**핵심**: Pro 조합은 트래픽이 튀어도 **사이트가 죽지 않고 과금으로 흡수**되며, **상한(예산 캡)은 직접 설정**해 폭탄 청구를 막는다. 무인 운영 원칙과 정합.

## 6. 유의점

1. **Vercel Hobby → Pro 전환은 사실상 필수.** 62K hits/day는 Hobby 비상업 약관·하드캡 저촉. Pro($20)가 약관·스케일·무중단을 동시 해소 — 이것이 본 분석의 실질 결론.
2. **위 사용량은 추정.** 정확화하려면 프로토타입을 실트래픽에 붙여 Vercel/Supabase 대시보드로 실측(이관 후 1회 캘리브레이션 권장). 특히 Vercel Edge Requests·R2 Class B(캐시 적중률 의존)가 변동 여지.
3. **미디어 R2 오프로딩은 선택이 아닌 전제.** 90GB/월은 R2 egress-무료로만 감당된다 — Supabase Storage나 Vercel Blob에 뒀다면 즉시 한도 초과.
